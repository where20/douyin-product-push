# 图文相符根因修复与复核 · 2026-11-05

## 为什么做这件事
11-02 / 11-04 的日志都记了同一个问题：出图与商品实际颜色/形态对不上（11-04 是 4/5 组不符）。
两次都只写了建议、**没有实施**（`git log --since=2026-11-01 -- scripts/` 当时无提交）。今天落实。

## 根因（实测定位，不是猜的）
1. **取色取的是缩略图噪声**：池子 color 来自榜单页 `s80x80_` 缩略图（仅 80×80），
   再做中心 60% 裁切 → 拿到的是促销色/背景色/噪点，不是商品色。
2. **product_en 按榜单类目猜**：一个榜单类目下混着完全不同的商品
   （"清洁工具簸箕"榜里既有扫把簸箕套装、也有 EVA 地刮/硅胶刮水器）→ 形态全错。
3. **低饱和色的色相是纯噪声**：#B2B4B6(不锈钢银灰) sat=0.022 → 落进 blue → "muted blue"。

## 修法（commit cf1da8d）
- `dy_pool.py`：`s80x80_` → `s800x800_` 大图；`dominant_color()` 改三级优先级
  ①商品名明确色词直采 ②strong 材质典型色直采（玻璃/不锈钢/硅胶/EVA/原木/竹制）
  ③大图网格投票 + 中心加权 + 材质先验；新增 `--recolor` 只重算 color（不重抓榜单）。
- `lib_dy.py`：新增 `_MATERIAL_RULES` / `_COLOR_RULES` / `detect_material()` /
  `detect_name_color()` / `derive_product_en()` / `analyze_product_color()`。
- `build_feed.py`：`_color_en` 补红轴兜底 + 低饱和(<0.12)按明度判黑白灰 +
  深色低饱和(sat<0.35)判 black；prompt 优先用 `color_en`；`color_en` 字段与 prompt 同源。

## 实测效果
- 5 组 ground truth 平均 ΔE(rgb)：旧 71~105 → 新 **54**；product_en 5/5 正确（旧逻辑形态错 2/5）。
- 今日 5 组出图**肉眼复核：5/5 图文相符**（修复前 4/5 不符）：
  - 100282201632 八海鸟布艺收纳箱 → 米白无纺布方箱 ✅
  - 100200049384 攸途航牛津布车载箱 → 炭灰车载收纳箱（带侧袋/把手）✅
  - 10223693917245 佳帮手 EVA 地刮 → 浅灰 EVA 地刮（不再是簸箕套装）✅
  - 100042591218 漫德莱 不锈钢扫把簸箕 → 金属簸箕 + 不锈钢杆扫把 ✅
  - 100327208050 GLASSLOCK 钢化玻璃保鲜盒 → 通透玻璃盒 ✅

## 新增踩坑
- **深色低饱和同样有噪声**：#16171C(悦卡收纳箱, 实为黑灰) sat=0.21 → "deep blue" → 会画成蓝箱子。
  → 深色区 sat 阈值 0.18 → 0.35，近黑一律 black（藏青 #1B2A4A / 深酒红 sat>0.6 不受影响）。
- **图床会瞬时 500**：15 张里 1 张核验返回 500，同一 URL 复探连续 3 次 200 → 服务端抖动，
  不是文件坏。重跑流水线复验即可，不必立刻重传（重传只会多一份图床垃圾）。
- **图床单张上传偶发返回非 JSON**（"Expecting value: line 1 column 1"）：
  publish_pack 没有单张补传口子，全量重传会产生 15 张图床垃圾
  → 用一次性脚本只补那一张并合并回 uploaded_urls.json（见 /tmp/dycheck/fix_one_upload.py）。
- **feed.json 的 color_en 字段与 prompt 实际用色不同源**：字段原本只填名色词/材质语义，
  布艺箱(无色词)字段是空串，而 prompt 走 `_color_en(hex)` 回落 → 已让字段兜底同源。
- **代理端口会时有时无**：今天 push 撞上 6696 无监听 → 直连 GitHub `Empty reply from server`，
  恢复后重跑即成功。判据永远看 SHA 区间行，不要看 exit code。
- **mmx 额度要省着用**：本次重出只花 10 张（cover+scene），尾图是 PIL 合成不计额度；
  后续重跑流水线全部幂等跳过（cover/scene 时间戳不变可自证）。
