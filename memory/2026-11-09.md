### 实现要点
- 图片**不落站点**，直接引用图床真实 URL（`cloudimgs.iepose.cn/api/images/douyin_{date}_p{id}_{role}.jpg`）。
  站点不打包 jpg，体积压到 164K；180 个图床 URL 全量复检 200。
- 页面无构建步骤，纯静态 + fetch 读 `data/*.json`；`?d=YYYY-MM-DD` 支持深链。
- 颜色点缀取自 `feed.json` 的 `color`（manifest 里没有这个字段）。

### 踩坑
- **`feed.json` 结构不统一**：10-29 到 11-09 的 feed.json 全是 **list**，
  不是 `{"posts": [...]}`。`build_site.py` 两种都要兼容，否则直接 AttributeError。
- **图床偶发 500**：12 并发核 180 个 URL 时有 1 个返回 500，复检（8 并发）全 200，
  是图床瞬时抖动不是文件丢了。单次 500 不代表裂图，要复检确认。
- **浏览器 ERR_BLOCKED_BY_ORB**：首屏加载时 2 张图被 ORB 拦，但 curl 看响应头完全正常
  （200 / image/jpeg / ACAO *）。是浏览器并发瞬时态，重载即恢复。**不要因此改图床 URL**。
- **SPA 的 `history.replaceState` 会触发自动化工具的 UNEXPECTED_NAVIGATION**：
  点日期 pill 只是改 URL，没有真实跳转，但 Browser 工具会报「页面意外变化」。
  判据看 URL 和 `.pill.on` 高亮，别把这个当 bug 去修。

### 后续

- 暂未接进 `run_daily.sh`，因为重新部署是 agent 侧动作、脚本里做不了。
