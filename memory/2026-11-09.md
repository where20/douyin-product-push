## 落地页上线（2026-11-09 15:30，流水线跑完后追加）

用户要求「部署到网站」，方案选定：**mavis drive 公网 URL + 每天一档历史可切换**。

- 公网地址: https://7topz32hhfou1.space.mcode.cn
- drive 节点 ID: `461441702687851`
- 新增文件: `scripts/build_site.py`（数据生成 + 体检）、`site/index.html`（页面）
- 站点数据: `site/data/{date}.json` × 12 + `history.json`，共 60 组 / 180 图，164K

### 实现要点
- 图片**不落站点**，直接引用图床真实 URL（`cloudimgs.iepose.cn/api/images/douyin_{date}_p{id}_{role}.jpg`）。
  站点不打包 jpg，体积压到 164K；180 个图床 URL 全量复检 200。
- 页面无构建步骤，纯静态 + fetch 读 `data/*.json`；`?d=YYYY-MM-DD` 支持深链。
- 颜色点缀取自 `feed.json` 的 `color`（manifest 里没有这个字段）。

### 踩坑
- **`feed.json` 结构不统一**：10-29 到 11-09 的 feed.json 全是 **list**，
  不是 `{"posts": [...]}`。`build_site.py` 两种都要兼容，否则直接 AttributeError。
- **图床偶发 500**：12 并发核 180 个 URL 时有 1 个返回 500，复检（8 并发）全 200，
  是图床瞬时抖动不是文件丢了。单次 500 不代表裂图，要复检确认。
- **浏览器 ERR_BLOCKED_BY_ORB**：首屏加载时 2 张图被 ORB 拦，但 curl 看响应头完全正常
  （200 / image/jpeg / ACAO *）。是浏览器并发瞬时态，重载即恢复。**不要因此改图床 URL**。
- **SPA 的 `history.replaceState` 会触发自动化工具的 UNEXPECTED_NAVIGATION**：
  点日期 pill 只是改 URL，没有真实跳转，但 Browser 工具会报「页面意外变化」。
  判据看 URL 和 `.pill.on` 高亮，别把这个当 bug 去修。

### 后续
- 站点是静态托管，**不跟 git push 自动更新**。要每天刷新需另加 cron（重跑 build_site + 重新部署）。
- 暂未接进 `run_daily.sh`，因为重新部署是 agent 侧动作、脚本里做不了。

## 治「内容还是复读」· 4 处根因 + 1 个 bug（2026-11-09 下午，用户追问后动手）

用户问「现在每天推动内容还是一样的？」→ 拿 12 天真实数据算了一遍，不靠感觉。

### 改之前的实测
| 层级 | 数据 |
|---|---|
| 商品跨天返场 | 60 个位置里 10 个重复 |
| 文案一字不差 | 60 条里 4 条 |
| 首句高频 | 只有 4 种，各 9-12 次 |
| 每天子类目 | 10-29~11-06 连续 9 天同一组 5 个 |
| 同家族扎堆 | 25 天里 11 天「5 条中 ≥3 条同属一大类」 |

### 根因与改法
1. **干货句库只有 3 条/类目**（文案重复真凶）→ 每类目扩到 10 条（69→330 条）+ `{word}` 占位符
   运行时填该商品自己命中的品类词（收纳箱/整理箱/收纳筐…），首句自然错开
2. **子类目顺序固定**（每天那 5 个不变）→ 按日期轮转 + **互质步长跨步铺开**
   同家族扎堆 11/25 → 5/27 天
3. **当天同子类目允许 2 次** → 养号期 `max_per_label=1`（放宽轮保留兜底）
4. **池子太小** 156→320 商品 / 19→30 子类目（见下）
5. **选品死循环（真 bug）**：`progressed` 只在真选中商品时置位 →
   各组首个商品全被「历史已发」跳过 → break → 放宽轮又把同样这 5 个选出来。
   早期 11 天恰好用完了每个类目的第一名（榜单第一），于是从 11-12 起每天循环同一组。
   看着像池子不够（当时还剩 96 个没用过），其实是死循环。→ 指针前进就算有进展。

### 池子扩容
- `dy_pool.py` 的 curl **无会话 cookie** → 第二个源起整片空页（池子长不大的根因）
  → 加 cookie jar + 源间隔 1.5s + 限流退避重试
- 6 个源 URL 缺 `key_` 前缀；补之前得确认标题里没有「优评」（那是栏目页不是榜单页）
- 新增 `dy_pool_expand.py`：扫现有源页导航区 → 23 个源带出 80 个候选、66 个验证通过
- 新增 10 个类目（浴室凳/管道疏通器/卫生间纸巾架/洁厕清洁/旅行洗漱套装/泡澡桶/拖把头/平板拖把/胶棉拖把/移动坐便椅），各手写 10 条干货
