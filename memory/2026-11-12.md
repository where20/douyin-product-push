## 排查与修复记录 (cron 任务 15:05 跑批后追加)

### 1. mmx 出图极慢 —— 不是配额, 是服务端 RPC 超时
- 现象: 第 1 张图跑了 8 分钟; 后续单张 1~8 分钟不等, 15 张跑不完 30 分钟命令时限
- 报错: `API error: rpc timeout: timeout=1m0s, to=amadeus-server-rpc-headless..., method=Play`
- 排除配额: `mmx quota show` → general 区间剩余 **88%** (明显不是额度用尽)
- 旁证: 简单 prompt 单测 14 秒出图; 同一条完整 prompt 180 秒超时 → **prompt 越复杂越容易被后端拖**
- 处理: 让脚本自带的 3 次重试兜底; 命令时限截断后**重跑 `run_daily.sh`** 续上
  (出图幂等, 已出的 5 张直接跳过, 不烧额度)。最终 15/15 全绿
- ⚠️ 别把"简单 prompt 快"当成"服务正常"的证据

### 2. 文案首句复读词 —— {word} 参数化的边界没处理
- 现象: 5 条里 1 条首句是「后备箱**后备箱收纳箱**要买能固定住的」
- 根因: 模板 `后备箱{word}要买能固定住的` 的字面前缀 + 商品命中词 `后备箱收纳箱` 本身带前缀
- 另有一类后缀重叠: `{word}疏通完要冲大量水` + word=`管道疏通` → `管道疏通疏通完要冲大量水`
- 修复: `build_feed.py` 新增 `_overlap_join()`(最大重叠拼接), 左边 1 字起 / 右边 2 字起
  - 右边只给 1 字: 「毛巾架」+「架子」= 「毛巾架子」是**另一个合法词**, 不能乱切
- 回归: 320 个池商品 × 全部模板 = 3104 组 → 重复块 **49 → 0**
- ⚠️ 今天已发布的 5 条**故意不回头改** —— `publish_pack --reuse-upload` 只比 key 不比内容哈希,
  改了 tip 复用旧 URL = 图上旧字 + 文案新字 = 图文不符 = 假带货。只让后续日期生效。

## 落地页刷新补充 (15:30 cron) — push 判定假阴性修复

### 现象
- 15:30 站点刷新这次 push, 脚本判 ❌「未推成功」, 但 GitHub API 核对 → 远端 main 已是 baef52d
- 原因: **包已送达但 sideband 连接断了** → 输出 "RPC failed / send-pack: unexpected disconnect",
  重试打印 "Everything up-to-date" → 日志里既没 SHA 区间行也没 `main -> main`
- ⚠️ "Everything up-to-date" 本身是**歧义**的(坏 pathspec 也打同样的), 不能直接当成功信号

### 修复
- `push_with_probe.sh` 的兜底判据**之前只写了注释没落地**(184 行处无条件 exit 1) → 本次补实现
- → 直接问远端真实 main SHA: SSH `ls-remote` 优先, 失败退 HTTPS → 跟本地 HEAD 比
- → 相等即判成功, 并 `update-ref` 对齐本地跟踪引用(让下次"远端已是最新"早退生效)
- ⚠️ 不能只比本地跟踪引用: 第 3 层 SSH 兜底是往 URL 推的,
  **不会更新** refs/remotes/origin/main → 那条路径上比相等会误判失败
- 实测两条通道都通: SSH ls-remote / HTTPS ls-remote 均返回 85030bd
